# MH3G 防具模型映射研究记录

状态：已应用到数据库 v3、资源包 v3 和完整人物试衣间
记录日期：2026-08-15

## 结论

MH3G 主程序包含可直接使用的防具模型映射，不需要按 Dex 顺序、名称、稀有度、
`Amr_ImgFile` 或 `plXXX` 目录顺序推测。

每个防具部位使用一张独立的 24 字节参数表。存档中的部位局部 ID 可以直接索引
对应记录：

```text
record = armor_table[save_type] + save_id * 24
male_model_id   = record[2]
female_model_id = record[3]
```

模型字段直接对应资源目录 `player/mod/{m,f}/plXXX/` 中的 `XXX`：

```text
record[2] = 2  -> 男性 pl002
record[3] = 2  -> 女性 pl002
```

男女通用防具的两个字段相同；男性限定防具只有 `record[2]` 非零，女性限定防具
只有 `record[3]` 非零。模型 ID `0` 不是普通防具模型，表示该部位没有独立防具
外观；完整人物试衣间使用同性别 `pl000` 的对应基础部位补全人物。

## 本次踩坑

第一版防具图鉴把 Dex `Amr_ImgFile` 外观组按首次出现顺序编号，再把该编号当成
`plXXX`。这个假设能够生成看起来完整的表，也能命中真实存在的 ARC 文件，但编号
没有游戏依据。

由此产生的典型错误：

| 防具系列 | 游戏真实模型 | 第一版模型 |
| --- | --- | --- |
| 轻皮 | `pl001` | `pl000` |
| 锁链 | `pl002` | `pl003` |
| 狗龙 | `pl003` | `pl015` |

用户看到锁链头盔显示为狗龙头，正是因为第一版把锁链错误绑定到 `pl003`，而游戏
参数明确表明 `pl003` 属于狗龙系列。

本次错误说明：

- ARC 路径存在，只能证明资源存在，不能证明装备与资源的对应关系。
- 名称前缀、位阶、稀有度和五件套关系适合生成套装分组候选，不适合生成模型映射。
- `Amr_ImgFile` 是 Dex 的外观引用键，数值及首次出现顺序都不能直接换算为
  `plXXX`。
- `record[0]` 是基础防御，不是模型编号。轻皮的基础防御和模型编号刚好都为 1，
  曾造成一次误判。
- 套装分组和模型绑定是两层数据：人工套装表可以决定五件如何排成一行，但模型
  必须由每件装备自己的游戏参数决定。

## 主程序证据

研究对象是从 MH3G ExeFS BLZ 解压得到的主程序 `.code`。以下地址采用加载后的
ARM 地址。

数据库构造函数位于 `0x0088bb60` 附近：

- `0x0088bb94` 把对象 `+0x84` 指向 `0x00bb6020`，这里是六张防具/护石参数表的
  指针数组。
- `0x0088bba4` 把对象 `+0x94` 指向 `0x00b99524`，这里是十二类武器参数表；它
  不是防具表。早期分析曾把这两组表混淆。
- 防具记录读取函数位于 `0x00889160`，按部位和局部 ID 返回 24 字节记录。
- 防具表数量位于 `0x00af7840`。

五个部位的运行时表地址如下：

| `save_type` | 部位 | 表地址 | 记录数（含 ID 0） |
| ---: | --- | ---: | ---: |
| 1 | 胸 | `0x00b9e7a0` | 382 |
| 2 | 腕 | `0x00ba0b70` | 363 |
| 3 | 腰 | `0x00ba2d78` | 371 |
| 4 | 腿 | `0x00ba5040` | 377 |
| 5 | 头 | `0x00b9c400` | 380 |

第六张表是护石相关数据，不参与防具模型选择。

已确认样本：

| 防具 | 部位局部 ID 示例 | `record[2]` | `record[3]` | 结果 |
| --- | ---: | ---: | ---: | --- |
| 轻皮 | 各部位 ID 1 | 1 | 1 | `pl001` |
| 锁链头盔 | 头 ID 3 | 2 | 2 | `pl002` |
| 小狗龙头盔 | 头 ID 10 | 3 | 3 | `pl003` |
| 眠狗龙 | 各部位对应 ID | 5 | 5 | `pl005` |
| 毒狗龙 | 各部位对应 ID | 171 | 171 | `pl171` |

人物装备加载代码会把选择出的模型号用于 `pl%03d` 资源路径。由此形成完整链路：

```text
装备部位 + 存档局部 ID
  -> 24 字节防具参数记录
  -> 男/女 model_id
  -> player/mod/{m,f}/plXXX/{part}_XXX.arc
```

`romfs/arc/ID/` 中的 12 个 ARC 已完整盘点，主要是名称 GMD、界面布局、纹理和
字体。`ID_res.arc` 可以确定存档 ID 名称数组，但不包含防具到 `plXXX` 的映射。

## 覆盖验证

使用当前图鉴数据库中已有明确存档映射的 1,600 件防具进行了交叉验证：

- 共检查 2,953 个“装备 × 适用性别 × 部位”组合。
- 男女通用装备的两个模型字段全部相同。
- 所有性别限定装备的非适用性别字段均为 0。
- 共引用 207 个非零模型编号，最大编号为 213。
- 所有非零编号都存在对应性别、部位的 ARC 文件。
- 三眼五件和增弹耳环等记录使用模型 ID 0；单件模型不能伪装成某个普通防具模型，
  但在完整人物模式下会明确使用 `pl000` 对应基础部位。

目前仍有 51 件 Dex 条目没有唯一存档 ID crosswalk。这些条目可以继续显示属性，
但在建立明确的局部 ID 前不能用 Dex ID 猜参数记录，也不能据此开放快速加入。

## 数据层修正规则

ExeFS 解析属于离线数据生成流程，不进入修改器运行时。数据库 v3 已增加
逐件、逐性别的权威映射，不再从套装表读取模型编号：

```text
armor_dex_id,save_type,save_id,male_model_id,female_model_id,source
```

固定数据流如下：

```text
用户持有的 MH3G ExeFS .code
  -> tools 中的离线导出器（校验 SHA-256、表地址和字段）
  -> 仓库内确定性 crosswalk/CSV
  -> build_encyclopedia.py
  -> data/encyclopedia.sqlite
  -> EncyclopediaData 查询接口
  -> 防具详情、模型预览和试衣间
```

前端只根据防具实体和当前性别查询数据库中的 `male_model_id` 或
`female_model_id`，再由资源管理器使用数据库返回的模型键加载 ARC。前端不得：

- 在用户机器上读取或反汇编 ExeFS。
- 硬编码主程序地址、24 字节记录偏移或部位表长度。
- 根据套装 ID、Dex 行号、名称或列表位置拼算 `plXXX`。
- 直接访问生成阶段的临时文件。

这样 ExeFS 版本变化只影响数据生成和校验；UI、模型查看器、试衣间及 portable 包
仍只依赖随程序发布的 SQLite 和独立资源包。

其中：

- `source` 固定记录 ExeFS 版本、主程序 SHA-256、表地址、记录大小和字段偏移。
- 生成器必须验证 `save_id` 没有越过对应部位的游戏记录数。
- 非零模型号必须找到对应性别和部位 ARC。
- 男女通用装备必须满足两个模型号相同。
- 性别限定装备必须满足不适用性别字段为 0。
- 模型 ID 0 必须进入显式的“无独立模型”状态；仅完整人物组合可使用对应
  `pl000` 基础部位补全身体。
- `mh3g_armor_sets.csv` 只维护位阶、职业、显示名称、顺序和套装成员；旧的
  `model_id` 字段已删除，不能再驱动渲染。

## v3 实施结果

### 1. 更换现有防具模型映射（已完成）

1. 编写确定性的 ExeFS 防具模型 crosswalk 导出器。
2. 固定主程序 SHA-256、五张表地址、24 字节记录大小和男女字段偏移。
3. 为 1,600 件已有存档映射的防具生成仓库内逐件 crosswalk/CSV。
4. 由现有确定性构建工具更新 `encyclopedia.sqlite` 和 manifest。
5. 让前端统一通过 `EncyclopediaData` 查询模型，不接触 ExeFS 或生成器常量。
6. 移除运行时的套装级模型推断；模型 ID 0 在完整人物中使用基础部位。
7. 用轻皮、锁链、狗龙、男女限定装备和五个部位建立数据层及前端回归测试。

### 2. 加入人物基础模型（已完成）

1. 解析男女 `pl000` 基础身体、`face000...`、`hair000...` 及对应 TEX/MRL。
2. 找出人物公共骨架、绑定姿势、骨骼层级、顶点权重和部位挂点。
3. 让现有 MOD 解析器正确执行骨骼蒙皮；禁止继续把未蒙皮的防具原始顶点当作
   最终姿态。
4. 每个部位只加载防具组件或基础组件之一，不叠加两份身体；透明材质后绘制。
5. 已批量验证 2,004 个防具 ARC 和 50 个脸/发型 ARC，并组合男女基础人物。

### 3. 加入试衣间（已完成）

1. 在同一人物骨架上装配头、胸、腕、腰、腿五件防具。
2. 按当前角色或手动选择的性别读取对应模型字段。
3. 支持单件替换、整套替换和混搭；缺失单件时保留人物基础部位。
4. 沿用模型框边缘的上下左右按钮旋转，不恢复鼠标拖动视角。
5. 显示当前五件名称、模型状态、技能、防御和耐性汇总。
6. 试衣操作只改变预览，不设置存档 dirty；“加入装备箱”仍走现有原子写入和
   主窗口保存流程。

### 4. 验收

- 锁链头必须显示 `pl002`，狗龙头必须显示 `pl003`。
- 男女限定防具只能加载适用性别模型。
- 五个部位分别抽查下位、上位、G 位、特殊装备。
- 人物站姿下胸、腕、腰、腿不能出现未蒙皮导致的压扁、散开或原点堆叠。
- 快速连续换装不能显示上一次请求的模型。
- 没有资源或单件解析失败时，属性、技能、素材和存档编辑功能仍可使用。
