# 长列表输入选择组件规范

## 目标

名称型长列表统一使用“可输入关键词筛选、明确选择后提交”的输入选择组件。组件基于
`QComboBox`、`QLineEdit` 和 `QCompleter`，由 `configureSearchableComboBox(QComboBox *)`
配置；它仍然是单选控件，不是可保存任意文字的自由输入框。

本规范同时约束新页面和现有页面。新增名称型长列表不得单独实现另一套点击、筛选、焦点或
提交逻辑。

## 适用范围

以下名称型列表必须使用该组件：

- 道具、武器、防具、护石、装饰珠和技能名称。
- 脸型、发型和声音。
- 装备类型筛选、新增装备类型、配装武器类型和配装技能条件。
- 护石类型、护石技能和装饰珠技能筛选。

男/女、比较符、孔数、语言、是/否等数量少且含义固定的枚举，继续使用普通不可输入
`QComboBox`。短枚举不应为了形式统一而改成关键词输入。

当新列表同时满足“候选主要靠名称辨认”且“逐项翻找明显不便”时，默认按长列表处理；若不
确定，应优先复用本组件，而不是新增只支持首字母跳转的普通下拉框。

## 交互规则

### 点击与焦点

- 点击输入区只让编辑框获得焦点，并允许用户正常定位光标或选择文字。
- 点击输入区不得强制调用 `showPopup()`，空关键词不得自动展开完整列表。
- 组件不得因点击、输入或刷新候选主动失焦。用户主动点击其他控件时仍按 Qt 正常失焦。
- 点击右侧下拉箭头可以主动查看完整列表。

### 筛选与补全

- 用户输入非空关键词后，在输入框下方显示匹配候选。
- 匹配对象是候选的完整显示文字，因此同时支持中文名和英文名。
- 匹配采用不区分英文大小写的包含匹配，不限定从名称开头匹配。
- 候选最多显示 20 行，超出部分由候选列表滚动查看。
- 空关键词只保留编辑状态，不自动显示候选；完整列表通过下拉箭头打开。

### 提交与取消

- 点击候选提交该候选。
- 按回车提交当前高亮候选；没有高亮但存在匹配项时提交第一项。
- 提交后输入框恢复候选的完整显示文字，并记录该候选的真实数据值。
- `Esc` 只关闭当前候选列表，不提交临时关键词，也不改变输入焦点。
- 未点击候选或未按回车的文字都属于临时关键词。用户使控件失焦时，必须恢复最后一次已提交
  的候选和完整显示文字。
- 无匹配项时按回车同样恢复最后一次已提交值，不生成新条目。

## 数据与业务状态

每个候选必须将可持久化的真实 ID 放入 `Qt::UserRole`。显示文字仅用于展示和筛选，不得作为
业务主键：

- 允许多个候选使用相同显示文字；提交时必须按 `UserRole` 区分，不能用 `findText()` 作为
  正常定位方案。
- 配置后的组件保存数据时必须调用 `searchableComboBoxCurrentData()`，不得从 `currentText()`、
  临时编辑文字或无效索引推导 ID。
- ID `0` 只有在用户明确选择对应候选（例如“无”）时才是有效值。无匹配项、无效索引或临时
  关键词不得回退成 ID `0`。
- 单纯输入、删除或取消关键词不得触发存档 dirty、配装 dirty、合法性重算、数据库查询或其他
  `currentIndexChanged` 业务逻辑。
- 只有点击候选、按回车、点击完整下拉列表中的项目，或程序明确设置新候选后，才视为选择
  变化并执行既有业务逻辑。
- 失焦恢复必须阻断选择变化信号，不能把恢复动作误报成一次用户修改。

搜索状态与已提交业务状态必须分开保存。当前统一控制器通过
`mh3gSearchableCommittedData` 和 `mh3gSearchableCommittedIndex` 保存最后一次提交状态；页面
代码不应直接改写这些动态属性。

## 接入要求

典型接入顺序如下：

```cpp
QComboBox *combo = new QComboBox(parent);
combo->addItem(displayName, stableId);
configureSearchableComboBox(combo);

const int selectedId = searchableComboBoxCurrentData(combo).toInt();
```

接入时还必须满足：

- 候选的 `UserRole` 在该列表中能稳定标识真实记录。
- 中英文搜索需要把两种名称都放入显示文字，或由统一模型提供可搜索文本。
- 业务层监听选择变化，不监听 `QLineEdit::textChanged` 或 `textEdited` 来保存数据。
- 动态重建候选模型时先保存已提交 `UserRole`，重建后按数据值恢复对应候选；不得只按显示文字
  恢复重名记录。
- 不得对已配置组件再次安装页面私有的 completer、点击事件过滤器或强制弹出逻辑。

统一实现位于
[`searchable_combobox.hpp`](../app/MH3U%20Save%20Editor%20GUI/MH3U%20Save%20Editor%20GUI/searchable_combobox.hpp)。

## 回归要求

修改统一组件或新增接入点后，至少运行：

```bash
./tests/run-searchable-combo-tests.sh
```

交互回归必须继续覆盖：

- 点击输入区保持焦点且不强制展开完整列表。
- 中文、英文、不同大小写和包含匹配。
- 鼠标点击及回车提交正确 `UserRole`。
- 重名候选仍按真实 ID 区分。
- `Esc` 只关闭候选列表。
- 未确认文字失焦后恢复原值，且不发出选择变化。
- 空关键词不自动弹出候选。

Windows Action 必须执行相同的离屏交互测试，避免平台打包版本与本地行为不一致。
