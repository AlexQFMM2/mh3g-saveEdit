# MH3G 资料库与实时模型功能决策记录

## 结论

MH3G 修改器不再继续内置武器/防具资料库、实时 3D 模型查看器和完整人物试衣间。相关界面、
数据库、生成工具、模型解析器和发布资源依赖已从正式分支移除。后续版本重新以存档读取、字段
映射、编辑安全性和跨平台存档兼容为核心。

本决策不包含纯文字与参数驱动的本地配装器。配装器不展示图鉴、图片或模型，只计算装备、
护石、装饰珠、技能、防御和耐性，并服务于“一键加入装备箱”与后续在线配装分享；当前路线见
[本地配装器与在线平台路线图](LOADOUT_PLATFORM_ROADMAP.md)。

## 为什么停止

资料库的数据页面本身可以实现，但“游戏内效果”的实时装备预览并不是普通的模型展示：

- 每件装备需要稳定的存档 ID、图鉴记录和实际模型三方映射。
- 人物需要正确处理性别、部位复用、基础身体、脸、头发、骨骼 remap 和多权重蒙皮。
- 游戏使用主机专用材质与渲染流程，包括 MRL 资源绑定、PICA200 Fragment Lighting、TEV
  组合器、Shininess/Fresnel LUT、环境立方体、球谐光照以及独立的色彩后处理。
- 3G、4G 和 GU 即使共享部分引擎概念，也有各自的数据规模、参数表、资源布局和渲染差异；
  完成 3G 不等于后两作可以直接复用。
- GU 的装备记录规模更大。虽然游戏会复用模型，但逐项 crosswalk、异常处理和视觉验收仍然
  会成为长期维护负担。

继续推进会把“存档修改器附带资料页”扩大成独立的游戏资源逆向与渲染器项目，并持续拖慢
GU、4G 和 3G 存档核心的修复。已经投入的工作证明该方向技术上可行，但不适合作为当前产品
的主线功能；停止是范围与维护成本决定，而不是简单的曝光度或模型参数尚未调好。

## 发布变化

- GitHub Action 不再下载 `MH3GResources` Release Asset。
- portable 包不再携带游戏 ARC、图鉴 SQLite、Qt SQL 插件或模型查看器依赖。
- 修改器界面只保留角色、道具箱和装备箱等存档功能。
- 存档 ID 的游戏资源校验成果继续保留并用于现有 CSV 数据层，这与资料库功能无关。

## 已确认但不再产品化的技术结论

完整解包已经确认，早期人物显示偏暗、偏棕并非单纯模型或骨骼错误，而是材质管线被过度
简化：MRL 的 12 字节资源绑定、176 字节 `CBMaterialStd`、程序化高光/Fresnel LUT、
`DefaultCube_CM.tex` 环境贴图和球谐系数都需要按游戏语义处理。肉眼接近游戏效果可以实现，
但要达到稳定、可移植、可维护的产品质量，还需要对每作分别实现和验证渲染路径；像素级一致
还需要捕获模拟器运行时的灯光、相机、阴影和色彩校正状态。

相关代码和调查过程没有改写历史，仍可从第一笔资料库提交 `e1cad61` 到最后一笔试衣间修复
提交 `4d7e94c` 查阅。若未来重新启动，应作为独立的资源查看器项目评估，不再直接绑定三个
存档修改器的交付节奏。
