# MH3G 手动配装器页面实施计划

## 目标

实现状态：首版已完成并随 `v1.3.0-beta.2` 上线；本地 JSON、在线广场、邮箱账号中心和装备箱
写入均已通过回归。Windows Release 已作为 prerelease 发布，客户端默认连接
`https://mhed.desk.65h26i.top`。MH3G 当前已转入维护阶段，最终完成范围和 MH4G 交接见
[MH3G 修改器阶段完成记录](MH3G_COMPLETION_RECORD.md)。

在现有中文浅色管理界面中增加“配装器”页面，完成以下闭环：

```text
选择武器
→ 按近战/远程筛选五部位防具
→ 选择护石和装饰珠
→ 实时计算技能、防御与耐性
→ 保存为本地配装
→ 一键创建到当前存档的装备箱
```

首版是手动配装器，不实现自动搜索、自动推荐或自动补珠。之后的配装广场负责发现和分享
成品配装，本地页面同时作为广场配装的查看、调整和写入入口。

最初的本地配装器批次不恢复资料库、图片、模型、试衣间或游戏资源包；后续阶段已经接入在线
账号和配装平台，但本地配装、JSON 与存档编辑在服务器不可用时仍可独立运行。

## 页面布局

左侧管理导航增加始终可用的“配装器”。未读取存档时仍可创建、打开和导出本地配装；
“一键加入装备箱”只有在当前已读取3DS或Wii U角色存档时可用。

页面在现有约 `1100×700` 主窗口和 `1366×768` 屏幕下完整可见，分为三个固定区域。

### 顶部操作栏

- 配装名称输入框。
- 性别选择；有存档时默认跟随当前角色，无存档时默认男性。
- `新建配装`、`打开配装`、`导出配装`。
- `一键加入装备箱`，与主窗口底部的“保存修改”明确区分。
- 配装页面自身的选择、试算、导入和导出不设置存档 dirty；只有一键加入成功后设置 dirty。

### 七个固定装备格

按固定顺序横向展示：

```text
武器｜头｜胸｜腕｜腰｜腿｜护石
```

每张卡片固定显示槽位名、当前装备名、稀有度、孔位占用、合法性颜色以及以下操作：

- 点击“选择”打开装备选择弹窗。
- `装饰珠`打开当前装备的珠子编辑弹窗。
- `清空`只清空该格，不影响其他六格。
- 名称过长时单行省略，悬浮提示展示完整中英文名和存档 ID。
- 合法装备使用普通边框，明确非法使用红色，证据不足使用黄色。

武器必须先确定近战/远程方向。轻弩、重弩和弓为远程，其余九类武器为近战。选择武器后，
五个防具选择弹窗默认只列出对应职业或通用防具；可打开“显示不适用装备”查看全部。
更换武器时不自动删除已经选择的防具，只把职业冲突标红并说明原因。

### 底部实时计算区

左侧约占三分之二宽度，展示技能矩阵；右侧展示防御、耐性、孔位和诊断摘要。底部区域可
随窗口拉伸，技能表内部滚动，不让整个页面的固定装备格随内容滚走。

## 装备选择弹窗

配装器必须新建独立的 `EquipmentPickerDialog`，默认约 `920×620`。它用于武器和五个防具部位，不是装备箱现有的
`QWeapon`、`QArmor`或`QCharm`单件编辑弹窗，也不得把这些弹窗简单换标题后复用：

- 现有单件编辑器面向某一条存档记录，展示编号、颜色和原始字段。
- 配装器选择弹窗面向整个SQLite候选集合，核心职责是搜索、技能点筛选、比较和选择。
- 数据库选择模式不修改装备箱；读取存档后可通过独立“从装备箱选择”弹窗只读查询具体实例，
  返回其逻辑装备、原页/格和已安装珠子给 `LoadoutModel`，不会就地编辑原装备格。
- 现有装备箱单件编辑器的行为和布局保持不变。
- 技能条件中的技能系下拉支持输入中文或英文关键词搜索；条件按每行两个排列，增删后自动重排。

配装器内的武器类型、技能条件、护石类型、护石技能和装饰珠技能等名称型列表，统一遵循
[长列表输入选择组件规范](SEARCHABLE_COMBOBOX_RULES.md)。临时关键词只用于筛选，不得改变
配装 dirty 状态或触发查询；只有明确选择候选后才提交真实 ID 并刷新结果。

防具技能筛选是选择界面的一级功能，不藏在详情页或二次弹窗中。护石改用独立的
`CharmPickerDialog`，不铺开全部自然组合。

弹窗的装备类别由用户点击的七格固定传入，不提供“装备类型/部位”下拉框，也不能在弹窗中
切换到其他部位：

- 点击头部格只查询并展示头部防具，标题为“选择头部防具”。
- 点击胸、腕、腰、腿时分别只展示对应部位。
- 点击护石格直接显示护石类型、孔数、技能1/点数和技能2/点数表单。
- 点击武器格展示武器，武器类型可以作为候选筛选条件，但不能切换成防具或护石。
- 武器、防具和护石均提供独立装备箱来源弹窗；按页/格保持原顺序并显示装饰珠，选择后关闭
  来源弹窗并回填当前配装，取消时保留原数据库候选窗口。
- Repository查询固定带入预期 `save_type`；用户确认选择时再次校验返回记录类型，防止界面状态
  或导入数据把其他部位写入当前格。

### 查询区

- 中文或英文名称搜索，输入后短延迟刷新，避免每个按键阻塞界面。
- 武器：武器类型、稀有度和孔数筛选。
- 防具：不显示部位选择器，部位由当前七格固定；支持稀有度、孔数、剑士/枪手、性别筛选。
- 防具查询区固定提供可追加的技能条件行，每行包含“技能系下拉框、比较符、技能
  点数输入框、删除条件”。
- 比较符支持 `>`、`≥`、`=`、`≤`和`<`，点数接受有符号整数；常用默认条件为 `≥ 1`。
- 技能条件行可动态添加和删除，不限定为一项。多个条件之间固定使用 AND，并全部针对候选
  单件装备自身的固有技能点计算，不使用整套合计，也不预先加入尚未选择的装饰珠效果。
- 例如同时添加“攻击 > 4”和“达人 > 5”，结果只显示自身攻击技能点大于4、且达人技能点
  大于5的防具。缺少其中任意技能的候选按该技能0点处理，不能进入结果。
- 候选表为每一个当前技能条件生成可见的技能点列，让用户直接看到命中数值，不能只显示
  “已匹配”。
- 武器本身没有普通技能点，因此武器模式隐藏技能条件行；武器珠子的技能在选择武器后通过
  装饰珠弹窗配置。
- `只显示已确认自然装备`默认开启；关闭后显示 DUMMY、非法和未确认记录，但保持颜色提示。
- 清除筛选不会改变当前七格配装。

护石的121,952种自然组合仅用于表单实时合法性查询，不一次性创建 Qt 行对象。页面和弹窗不直接执行 SQL，
所有查询通过 `GameDataRepository`。

### 候选区与详情区

中间候选表按当前槽位显示必要列：

- 通用列：名称、稀有度/品级、孔数、合法性。
- 武器追加类型、攻击、孔位和防御加成；完整会心与属性值保留给后续数据展示迭代。
- 防具追加初始/最终防御、五耐性以及每个筛选技能的实际点数；多个技能条件分别占一列。

右侧详情显示完整中英文名、真实 `save_type + save_id`、全部参数、技能点及诊断原因。双击候选
或点击“选择此装备”只更新本地 `LoadoutModel`，不会修改存档。

## 装饰珠弹窗

武器、五件防具和护石都可打开 `DecorationEditorDialog`。默认宽度加大为约 `1120`，左侧候选区优先分配约 `750`像素：

- 顶部显示天然孔数、已占孔数和剩余孔数。
- 最多保存装备记录能够容纳的三个珠子 ID；多孔珠仍只占一个记录位置，但按真实孔数计费。
- 候选支持中英文名称、占孔数和技能系/最低点数筛选。
- 列表显示装饰珠的全部正负技能点，不只显示主技能。
- 孔位超限、DUMMY或映射未确认使用红/黄色说明，但不自动清除、不替换，也不阻止用户保留
  当前选择。
- 关闭时选择“应用/放弃”；应用只更新本地配装模型。

## 技能矩阵

技能表固定列为：

```text
技能系｜武器｜头｜胸｜腕｜腰｜腿｜护石｜合计｜发动技能
```

计算与显示规则：

- 武器列通常只有武器装饰珠贡献。
- 五个防具列包含该件防具的原生技能点和装饰珠技能点。
- 护石列包含护石的两项固有技能点和护石装饰珠技能点。
- 正数显示蓝色 `+N`，负数显示红色 `-N`，零显示 `—`。
- 达到正面发动阈值的行使用蓝色选中效果，达到负面阈值的行使用红色提示。
- “发动技能”列显示当前点数对应的最高已发动技能；未发动时显示距离最近阈值尚差的点数。
- 默认只显示总计非零的技能系，可切换“显示全部技能系”。
- 默认排序为已发动正面技能、已发动负面技能、接近阈值、其余非零技能；同组按技能树 ID
  稳定排序，避免每次刷新跳行。
- 单元格悬浮提示拆分“装备固有 + 装饰珠”的贡献。

### 胴系统倍加

数据库已确认技能树 ID `1` 为“胴系统倍化 / Torso Up”，发动阈值为1。计算器必须按显式
技能 ID 处理，禁止按中文名称判断：

- 每一件带胴系统倍加的非胸部防具，额外复制一次胸部防具固有技能和胸部全部装饰珠技能。
- 多件胴系统倍加分别累加。
- 不复制武器、其他部位或护石贡献。
- 对被复制的技能，该部位单元格显示实际增加的点数并用 `胸×1` 悬浮说明；胴系统倍加自身
  保留专用标记，不作为普通可累计技能点误算。
- 胸部为空时复制贡献为零。

## 防御、耐性和孔位汇总

右侧摘要随任意装备或珠子变更立即刷新：

- 初始防御：五件防具基础防御之和，加武器自带防御。
- 最终防御：五件防具数据库最大防御之和，加武器自带防御。
- 修改器不编辑防具强化等级；初始/最终两组数值只是配装参考。
- 火、水、雷、冰、龙耐性分别求五件防具之和。
- 总孔数、珠子实际占孔数和剩余孔数。
- 已发动正面技能数量、负面技能数量、非法和未确认诊断数量。
- 任一参数缺少证据时对应值显示 `—`或黄色“部分未知”，禁止把缺失值静默当成零。

技能造成的战斗中防御或耐性加成首版只在发动技能中展示，不伪造游戏最终状态公式。

## 模型、计算器与接口

新增独立本地模型，避免页面控件成为数据权威：

- `LoadoutModel`：保存七个装备选择、各自装饰珠、性别、名称和本地修改状态。
- `LoadoutCalculator`：纯计算技能矩阵、胴系统倍加、防御、耐性、孔位和诊断；不得修改模型或
  存档。
- `LoadoutPage`：页面协调、七格卡片和实时摘要。
- `EquipmentPickerDialog`：按槽位查询并返回一个逻辑装备选择。
- `CharmPickerDialog`：直接编辑护石类型、孔位和两项技能，并实时显示自然合法性。
- `DecorationEditorDialog`：编辑某个装备格的珠子列表。
- `LoadoutFile`：版本化 JSON 的导入、导出和完整解析。
- `LoadoutSaveBridge`：把完整配装事务式加入装备箱。

`GameDataRepository` 增加分页候选查询、完整武器/防具详情、护石组合和装饰珠查询接口。UI 不
持有 `QSqlQuery`，存档核心也不依赖 Qt 表格控件。

## 本地配装文件

扩展名固定为 `.mhloadout.json`，首版逻辑格式为：

```json
{
  "schema": "MH_LOADOUT",
  "schema_version": 1,
  "game": "mh3g",
  "data_version": "<mh3g.sqlite manifest hash>",
  "name": "套装名",
  "gender": "male",
  "weapon": {
    "save_type": 7,
    "save_id": 1,
    "decorations": []
  },
  "armor": {
    "head": {"save_type": 5, "save_id": 1, "decorations": []},
    "chest": {"save_type": 1, "save_id": 1, "decorations": []},
    "arms": {"save_type": 2, "save_id": 1, "decorations": []},
    "waist": {"save_type": 3, "save_id": 1, "decorations": []},
    "legs": {"save_type": 4, "save_id": 1, "decorations": []}
  },
  "charm": {
    "class_id": 1,
    "slots": 0,
    "skill1_id": 0,
    "skill1_points": 0,
    "skill2_id": 0,
    "skill2_points": 0,
    "decorations": []
  }
}
```

名称、技能合计、防御和耐性不作为权威数据保存；导入后始终使用当前数据库重新查询和计算。
文件不包含存档路径、角色名、原始装备字节或平台偏移。版本不兼容时明确报错，不按名称猜测
替换装备。这个格式验收后直接作为未来配装广场的客户端协议基础。

## 一键加入装备箱

读取存档后一键加入按钮始终可点击。七格不完整时列出缺少部位；完整时固定创建武器、五件防具和护石共七条记录，并写入各自装饰珠：

1. 完整解析七格并收集所有合法性诊断。
2. 验证每件装备和珠子都有明确存档 ID；映射缺失属于无法安全编码，可以阻止写入。
3. 预留七个空装备箱格；空格不足时不做任何改变。
4. 在临时装备箱副本中按武器、头、胸、腕、腰、腿、护石顺序构造记录。
5. 新建防具的强化值使用初始值0，之后交由游戏内强化。
6. 参数合法性风险只显示红色/黄色摘要，不要求二次确认，也不阻止写入。
7. 全部构造成功后一次性替换内存装备箱并设置主窗口 dirty，刷新装备箱页面。
8. 不自动穿戴、不自动保存磁盘；用户仍通过主窗口“保存修改”提交。

3DS与Wii U分别沿用现有字节序和文件布局，配装模型与JSON不保存平台偏移。

## 验证与验收

### 计算测试

- 单件防具、护石和正负装饰珠的技能点逐列与合计一致。
- 正面多级阈值、负面阈值、未发动差值和稳定排序正确。
- 一件及多件胴系统倍加正确复制胸部固有技能和胸部珠子，不复制其他列。
- 武器防御、五件防具初始/最终防御及五耐性求和正确。
- 零孔、一至三孔、多孔珠、超孔和部分未知参数显示正确。
- 计算和预览过程不改变任何存档字节。

### 界面测试

- `1366×768` 下七格、技能表、防御耐性摘要和主窗口底部按钮全部可见。
- 武器切换正确更新近战/远程筛选，已有冲突装备只标红、不被自动清空。
- 中文/英文搜索、多技能 AND、最低点数、性别、职业、孔数和合法性筛选正确。
- 12万护石组合使用分页查询，打开弹窗和连续筛选不冻结界面。
- 七格和装饰珠任一变化都只触发一次一致的实时重算。

### 文件与存档测试

- JSON重复导出内容稳定，导入后技能、防御和耐性重新计算一致。
- 版本错误、重复字段、越界数值和未知ID在完整解析失败时不改变当前配装。
- 3DS与Wii U样本一键加入只改变预留的七条装备记录。
- 箱满、映射缺失或批量构造中途失败时内存逐字节不变。
- 一键加入后只设置dirty，点击主窗口保存前磁盘文件不变。
- 非法或未知参数只提示，仍可写入；文件尺寸、数组边界和磁盘失败继续阻止操作。
- Qt 5.15本地构建、离屏冒烟测试和Windows Action通过。

## 实施顺序

1. 扩充只读Repository查询和计算所需的强类型数据接口。
2. 实现 `LoadoutModel`、`LoadoutCalculator`及纯计算测试。
3. 实现七格页面和装备选择弹窗。
4. 实现装饰珠弹窗、技能矩阵及防御耐性摘要。
5. 实现版本化本地JSON导入导出。
6. 实现事务式一键加入装备箱及3DS/Wii U字节回归。
7. 完成Qt冒烟测试、Windows Action和中文使用文档。

首版本地配装器验收后再冻结广场协议；自动配装器作为后续独立能力，第一版只在 MH3G
上验证，确认搜索结果、取消和存档写入边界后再抽象到 MH4G/MHGU。

## 自动配装器（MH3G 第一版规划）

### 目标与边界

自动配装必须完全在用户电脑本地运行，不把存档、搜索条件或中间结果上传服务器。它复用本地
`GameDataRepository` 和 `LoadoutCalculator`，输出标准 `loadout_model_t`，因此搜索结果可以
直接回填当前配装器并沿用现有预览、导出、发布和“一键加入装备箱”流程。

第一版弹窗的左侧是条件表单，右侧是持续增长的结果列表：

```text
┌──────────────────────┬─────────────────────────────────────────────┐
│ 搜索条件              │ 阶段、倒计时进度条、已检查状态数             │
│                      ├─────────────────────────────────────────────┤
│ 近战/远程             │ 暂停/继续、取消、任务状态                    │
│ 武器孔数              ├─────────────────────────────────────────────┤
│ 技能 1                │                                             │
│ 技能 2                │ 每条：装备摘要、技能、合法性、评分             │
│ 技能 3                │       [添加此配装到配装器]                   │
│ 最大时间              │                                             │
│ [清空] [开始搜索]      │                                             │
└──────────────────────┴─────────────────────────────────────────────┘
```

默认宽度建议约 `1180×720`，左侧约占 30%，右侧约占 70%；左右使用 `QSplitter`，最小宽度下
不让表单标签或主要操作按钮被截断。结果区独立滚动，进度与控制栏固定在右侧顶部，不随结果滚走。

- 方向：`近战` / `远程`。远程固定对应轻弩、重弩、弓，其余武器为近战。
- 武器孔数：`不限` 或 `0..3`，表示武器天然孔数下限/精确条件需要在产品定稿时二选一；
  第一版采用“至少 N 孔”，避免把有更多孔的武器无故排除。
- 搜索域固定为自然合法配装：只搜索已确认装备、合法孔位和数据库中的自然护石点数组合。
  第一版不提供“允许非法”开关，不计算超孔装珠或护石任意点数；这样结果可验证、可排序，
  也避免把大量实验性结果混入普通用户搜索。
- 需要发动的技能：1--3 个可搜索的“发动技能”选择框，直接选择例如“攻击力提升【大】”，
  而不是只选“攻击”技能系。目标保存 `active_skill_id + skill_tree_id + threshold`，阈值从数据库
  `active_skills` 读取，不能写死为 10 点。同一技能系重复选择时保留要求更高的一档；负面发动
  技能不作为搜索目标候选。
- 最大计算时间：建议限制在 `1..60` 分钟，默认 1 分钟。时间预算只约束搜索任务，不阻塞
  主窗口。
- 左侧提供“清空”按钮，只清空本次搜索条件和结果，不清空当前已编辑的配装模型。

点击“开始搜索”后打开搜索弹窗。弹窗关闭前必须提示“关闭将结束本次搜索，已找到的结果仍
可在当前窗口查看”；确认关闭才终止任务。搜索运行中可随时暂停或取消；暂停冻结剩余时间，
取消立即结束并丢弃未完成的工作。若达到截止时间仍无结果，右侧显示明确的“暂无找到合适的
配装”，并给出减少目标技能、降低技能等级、放宽武器孔数或增加计算时间的建议，而不是只显示 0。

### 结果与任务生命周期

每条结果显示：武器、头/胸/腕/腰/腿、护石、发动技能、总孔/已用孔和搜索评分；
提供“添加此配装到配装器”按钮。添加只替换/回填当前 `LoadoutModel`，不关闭弹窗；若当前
模型有未导出的修改，先确认是否覆盖。添加成功后保留弹窗，用户可以继续比较并添加另一条
结果。结果需要按规范化配装内容去重（不因同一组合的遍历路径不同而重复展示）。

进度区包含：

1. 环形或线性倒计时进度条（剩余时间/总预算）和已用时间；这是时间进度，不宣称为完整
   搜索百分比。
2. 当前阶段（候选预处理、护具组合、护石组合、装饰珠补足）及已检查状态数。
3. 暂停/继续、取消按钮；按钮状态和键盘焦点必须清晰可见。

### 为什么不是简单笛卡尔积

MH3G 数据中每个防具部位约 150--300 个可用候选，护石自然组合约 121,952 条，装饰珠约
230 条。直接枚举武器 × 五件防具 × 护石 × 珠子会在第一层就产生无法接受的组合数。
问题也不只是普通背包：

- 五个部位各只能选一个，且有近战/远程、性别和部位类型约束。
- 每个装备同时贡献多个技能维度和孔位容量，目标是满足多个技能阈值而非最大化一个价值。
- 胴系统倍化（技能树 ID 1）让非胸部装备的贡献依赖胸部选择，不能把各部位完全独立计算。
- 护石有品级、孔数、技能位置、点数和技能对的自然生成约束。
- 珠子每件最多三个记录、每颗占孔数不同，并可能有正负技能点。

因此采用混合求解器：

1. **候选预处理**：按方向、性别、武器孔数、部位和已确认映射裁剪武器/防具。候选按所需
   技能的正向潜力和孔数排序。
2. **部位状态 DP**：以胸部为先导，逐步加入头、腕、腰、腿。状态至少包含目标技能
   的点数向量、各部位天然孔数和胴系统倍化次数/胸部贡献版本。对同一（技能向量
   上界、孔数、胴计数、约束标记）保留支配状态，删除“技能不更多且孔数不少、评分更差”的
   状态。技能点对搜索只需截断到目标阈值附近，避免无意义的大向量。
3. **护石合并**：按自然组合查询与目标技能相关的护石，再与部位状态做向量合并；品级、孔数、
   技能位置、技能对和点数均必须存在于自然组合表，并复用现有校验器复核。
4. **装饰珠补足**：对每个剩余状态使用有界多维背包/小型 DFS，每件最多三个珠子记录，并以
   该件天然孔位作为硬上限。孔位是七个独立容器，不能借用其他装备的剩余孔。用“剩余最大
   可达技能上界”剪枝；达到全部目标后仍可继续探索，以便在时间未耗尽时返回下一个更优或不同结果。
5. **武器与评分**：方向和孔数已在候选阶段固定；最终按目标技能全部发动、剩余孔、
   防御/耐性和稳定 ID 生成可解释评分。评分只用于排序，不能改变合法性结论。

这意味着 DP 是“部位组合和珠子补足”的状态压缩工具，护石自然规则、胴系统倍化和结果枚举
仍需要约束检查与分支定界配合。

### 搜索域与约束

自动配装第一版只计算自然合法域。装备与装饰珠必须是已确认、可解析的数据库记录；近战/远程、
性别和部位必须适用；护石品级、0..3 孔、技能 ID、技能位置、技能对、点数必须存在于自然
生成规则；每件装备最多三个珠子记录，且珠子实际占孔不能超过该件天然孔数。护石的 121,952
条自然组合直接作为候选索引，不生成任意点数；任何不满足这些条件的分支立即剪枝并计入调试
统计，不展示为搜索结果。

### 可暂停的本地执行架构

不能直接在 GUI 线程中调用现有 `GameDataRepository` 查询：Qt SQL 连接属于创建它的线程，
把单例连接交给后台线程会产生线程亲和性和并发问题。开始任务时应在 GUI 线程创建不可变的
`LoadoutSearchSnapshot`（或由 worker 自己打开只读 SQLite 连接），其中包含候选装备、技能阈值、
护石组合和珠子技能向量；worker 只处理普通 C++ 数据，不触碰 QWidget、存档指针或全局 SQL
连接。

建议组件：

- `LoadoutSearchRequest`：方向、武器孔数、目标发动技能、时间预算、性别/数据版本。
- `LoadoutSearchSnapshot`：经过版本校验的只读候选和规则快照。
- `LoadoutSearchWorker`：`QThread` 中运行，持有 deadline、暂停条件变量和取消原子标志。
- `LoadoutSearchResult`：完整 `loadout_model_t`、摘要、诊断、评分和稳定指纹。
- `AutoLoadoutDialog`：左右分栏、倒计时、阶段状态、结果列表和生命周期确认。

worker 每处理一个可中断批次就检查取消标志和暂停条件，并通过 queued signal 发送进度/结果；
不得持有 GUI 锁等待用户操作。倒计时在 worker 的单调时钟上计算，暂停时累计暂停时长，
避免系统时间调整导致提前或延后结束。搜索完成、取消或关闭后释放快照和线程，不能残留后台
任务继续访问已销毁页面。若有限搜索域已在截止时间前穷尽，应立即显示“搜索完成”，不为了
走完倒计时而空转；“找到结果后继续搜索”只持续到搜索域穷尽或时间/用户操作终止。

### 关闭、崩溃与异常退出安全

自动搜索只使用主程序内的 `QThread`，不启动 `QProcess`、脚本或独立搜索可执行文件，因此
不会留下可脱离修改器生命周期的孤儿进程。弹窗的 `closeEvent` 必须统一经过以下顺序：

1. 搜索运行中先弹出确认；取消关闭则继续运行，确认关闭则设置取消标志并停止接受新结果。
2. worker 在下一个可中断批次检查标志，发送 `finished/cancelled` 信号；GUI 等待线程退出后
   才销毁 worker、快照和弹窗。不得直接 `delete` 正在运行的 worker，也不得用 `terminate()`
   终止持有 C++/Qt 对象的线程。
3. worker 不保存 QWidget、主窗口或存档指针，只通过 queued signal 回传值对象；弹窗销毁后
   不会有回调访问悬空界面。结果尚未“添加到配装器”前只存在于搜索窗口内，异常结束不会改
   当前模型或磁盘存档。

程序崩溃、断电或被系统强制结束时，整个主进程及其线程由操作系统一起回收，不会留下后台搜索
进程；由于搜索只使用内存快照，也不会留下必须清理的临时数据库或锁文件。为避免正常关闭时
卡住，求解器每处理有限数量候选就检查取消标志，并在测试中验证关闭确认后线程能在限定时间内
退出。若未来确实需要外部并行进程，必须另做进程句柄、父进程死亡检测和退出清理设计，不能
直接复用本方案的线程关闭逻辑。

### 第一版验收与性能门槛

- 同一数据版本和条件下，结果指纹顺序稳定；重复结果不会超过一条。
- 目标发动技能均达到数据库定义的阈值；所有结果通过自然装备、护石和珠子规则，且无超孔。
- DUMMY/unknown ID、近战远程或性别冲突、无效护石品级/孔数/技能位置/技能对、重复技能以及
  第四颗装饰珠均必须被剪枝，不得出现在结果列表。
- 近战/远程、武器孔数、护石孔数、胴系统倍化和装饰珠占孔均按现有计算器结果复核。
- 点击暂停后技能、结果数和剩余时间冻结；继续后可恢复；取消和关闭不会修改当前配装或存档。
- 首条结果出现后搜索仍继续，直到用户暂停、取消或时间耗尽；“添加到配装器”不关闭弹窗。
- 时间耗尽无结果显示建议性空状态；不能出现空白结果区或仅有“0 条”。
- 在基准电脑上开始搜索后 GUI 交互保持可用，首条结果应在可接受时间内出现；建立固定基准
  条件后记录候选数、状态数、首条结果时间和单位分钟产出结果数。
- 自动搜索只生成内存 `loadout_model_t`；写入装备箱仍必须经过现有显式按钮，不自动保存磁盘。

### 实施顺序

1. 把 `LoadoutCalculator` 的目标技能阈值、自然规则和候选字段整理成线程安全快照接口。
2. 先实现无界面、可重复的部位 DP + 护石合并 + 珠子补足测试，固定结果指纹和剪枝正确性。
3. 实现 `LoadoutSearchWorker` 的暂停、取消、deadline 和结果去重信号。
4. 实现 `AutoLoadoutDialog` 左侧条件表单、清空和右侧结果/倒计时/生命周期交互。
5. 接入 QLoadout 的“自动配装”入口，验证回填、覆盖确认、继续添加和现有导出/发布流程。
6. 以 MH3G 数据和真实样本做性能回归；通过后再评估抽象到 MH4G，最后才考虑 MHGU。

### 后续游戏边界

MH4G 自动配装沿用“只搜索可确定候选”的原则，并明确排除数据库中 `is_relic=1` 的发掘武器。
发掘武器的攻击、属性、斩味、升级等随机参数组合不进入候选生成、评分或结果回填；用户仍可在
手动配装器中选择和编辑发掘武器。普通武器是 MH4G 自动搜索的唯一武器来源。发掘防具是否进入
MH4G 自动搜索不在本次 MH3G 第一版中决定，需要结合其技能与固定珠数据另行评估。
