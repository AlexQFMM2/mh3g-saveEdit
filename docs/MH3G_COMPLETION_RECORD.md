# MH3G 修改器阶段完成记录

## 阶段结论

截至 2026-08-18，MH3G / MH3U 修改器的计划内功能阶段性完成，项目由功能开发转入维护状态。
当前桌面版本为 `v1.3.0-beta.2`，对应客户端提交 `bed6add`；在线平台对应提交为
`686bcbf`。Windows 便携包已作为 GitHub prerelease 发布：

<https://github.com/AlexQFMM2/mh3g-saveEdit/releases/tag/v1.3.0-beta.2>

“阶段完成”表示现有闭环已经可用，后续仍会处理明确缺陷、安全问题和经过验证的数据修正；
不再为 MH3G 主动扩展高风险或低收益的新存档字段。后续跨作工作已转向 MH4G，其配装器、
配装广场和一键导入的本地整合已经完成并进入 `main` 构建验证。

2026-08-18 的维护批次进一步加入配装器装备箱来源弹窗：武器、防具和护石均可按原始页/格
选择当前存档中的实例，并把已安装装饰珠及护石参数直接带入配装；同时统一修复 Windows/Linux
下复选框只有勾号、缺少可见边框的问题。该批次通过 `main` 分支 Windows Action 生成测试包，
不改变线上平台部署版本。

## 已完成能力

### 存档核心

- 自动识别 3DS 35,328 字节角色文件和带36字节头的 Wii U 35,364 字节角色文件。
- 分别按3DS小端、Wii U大端读取和写回，不对两种格式做不安全的整份存档转换。
- 人物、道具箱和装备箱统一在 Qt 管理界面中编辑；保存使用原路径原子替换并明确提示结果。
- 未修改打开保存保持逐字节一致；修改只触及目标字段，未知值和未使用槽保持原样。
- 道具箱和装备箱支持版本化 CSV 批量导入导出，导入先完整校验再一次性应用。

### 数据与装备编辑

- 运行时静态数据统一为只读 `data/mh3g.sqlite`，不再依赖散落 CSV。
- 存档 ID 以游戏 `ID_res.arc` 完整数列为权威；Dex 和原生参数只补充属性，不把第三方主键
  或名称匹配结果写入存档。
- 支持道具、十二类武器、五个防具部位、护石和装饰珠编辑。
- 武器、防具、护石和装饰珠合法性提供明确原因；自然护石规则来自原生组合记录，并能说明
  品级、孔数、技能位置、精确点数集合和技能对问题。
- 非自然装备只提示风险，不限制应用、导入或保存；结构损坏、未知 ID、越界和空间不足仍会阻断。
- 道具箱、装备箱使用虚拟表格和按需缓存，避免为数千格提前创建完整单元格控件。

### 统一长列表交互

- 道具、装备、装饰珠、技能、护石、脸型、发型和声音等名称型长列表均可输入中英文关键词
  做不区分大小写的包含筛选。
- 点击输入区只获得焦点，不强制展开完整列表；点击箭头仍可主动查看全部候选。
- 只有点击候选或按回车才提交真实 ID；未确认文字失焦后恢复此前值。
- 临时搜索词与业务状态分离，不触发存档 dirty、合法性计算或配装查询。
- 男/女、比较符、孔数、语言等短固定枚举继续使用普通不可输入下拉框。

### 本地配装器与一键加入装备箱

- 支持武器、头、胸、腕、腰、腿和护石七格手动配装，以及各部位最多三个装饰珠。
- 防具支持中文/英文名称、职业、性别、孔位及多个技能条件 AND 筛选。
- 读取存档后可从独立装备箱弹窗选择武器、防具和护石；弹窗保留原页/格，显示三颗装饰珠，
  支持按装备名、珠子名和位置筛选，同名实例不会因列表重排失去来源信息。
- 实时计算技能矩阵、发动技能、胴系统倍加、初始/最终防御、五耐性、孔位和全部风险原因。
- 支持版本化 `.mhloadout.json` 导入导出；配装 dirty 与存档 dirty 相互独立。
- 一键加入装备箱先预留七个空格并构造全部记录，全部成功后才一次性写入内存。
- 一键加入不自动穿戴、不直接保存磁盘；用户仍须在主窗口确认保存。
- 3DS 与 Wii U 使用各自正确的记录字节序，但共享同一套逻辑配装内容。

### 在线配装闭环

- 修改器默认连接 `https://mhed.desk.65h26i.top`，并允许用 `MHED_DESK_API_URL` 覆盖。
- 匿名用户可浏览配装大厅，按装备、发动技能和合法性筛选；装备与发动技能多选按 AND 处理。
- 列表提供配装名、发布者公开昵称、发动技能、防御、五耐性、点赞、举报和详情。
- 详情使用只读配装器弹窗，不跳转页面；用户确认后才在弹窗中一键加入自己的装备箱。
- 登录用户可修改昵称、查看获赞数、发布配装、删除自己的配装、点赞和举报。
- 服务端重新计算装备与技能索引、合法性、风险摘要和内容指纹；相同逻辑套装不能通过改名
  重复发布。
- 服务端只接收规范配装 JSON，不上传完整存档、角色名或存档路径。

### 账号、治理与部署

- 平台使用 PostgreSQL、Go API、React Admin/Web 和 Docker Compose 部署。
- 支持超级管理员、角色权限、普通用户、会话、举报、软删除和审计日志。
- 邮箱注册、邮箱登录、绑定/更换邮箱、忘记密码和重置密码的代码闭环已经完成。
- 邮件 Provider 固定使用 AOKSend API v2，密钥由生产环境主密钥加密保存；后台提供配置、余额
  查询、测试发送和最近发送记录。
- 生产 AOKSend 是否启用属于部署配置，不影响已有账号登录、本地编辑和配装大厅功能。

## 验证与发布门禁

- `tests/run-save-format-tests.sh`：3DS/Wii U 不修改往返、字节序、道具与装备传输。
- `tests/run-equipment-validator-tests.sh`：装备、珠子、护石及详细风险诊断。
- `tests/run-loadout-tests.sh`：查询、计算、本地 JSON、事务式装备箱写入和真实存档夹具。
- `tests/run-searchable-combo-tests.sh`：输入筛选、焦点、点击/回车提交、失焦恢复和重名 ID。
- Windows Action 校验生成数据、SQLite 与 Qt SQL 驱动、OpenSSL/HTTPS、主窗口、配装器、账号
  中心和长列表交互，并生成 portable ZIP。
- 发布包不携带 CCI、ARC、模型、贴图或其他游戏资源。

## 明确不做与风险边界

- 不恢复武器防具资料库、图片、模型预览、人物试衣间或游戏资源包。
- 不实现自动配装搜索或自动补珠；配装发现由公开广场承担。
- 不修改防具强化等级，游戏内强化继续由游戏系统完成。
- 不把“合法性”变成保存限制；修改器继续遵循“解释风险，但不替用户作决定”。
- 不做3DS与Wii U整份角色存档互转，只提供已验证的道具箱和装备箱逻辑数据传输。
- 不开放奇面族编辑。面具、舞蹈和特技解锁与剧情、任务、交易及成长进度关联，直接改位可能
  造成流程状态不一致；个人方案在游戏内已可调整，写入未解锁内容也会制造异常状态。
- 奇面族资源编号、茶茶当前面具、共享火龙面具获得位等逆向结果只作为研究资料保存；面具
  熟练度在完整字段和关联状态确认前也不提供写入。

奇面族的完整证据见 [MH3G 奇面族修改研究记录](SHAKALAKA_RESEARCH.md)，资料库停止原因见
[资料库功能决策记录](ENCYCLOPEDIA_DECISION.md)。

## 维护规则

MH3G 后续只接受以下类型工作：

1. 可复现的崩溃、错误写入、兼容性或交互缺陷。
2. 存档边界、数据 ID、计算公式和合法性规则的确证修正。
3. 平台接口兼容、安全更新、构建依赖和发布流水线维护。
4. 不改变产品边界的小型可用性改进。

新增高风险字段、游戏资源浏览、模型渲染或大型资料库功能不进入 MH3G 维护线。涉及跨作的新
能力优先在统一协议和对应游戏仓库中实现。

## 跨作状态：MH4G 本地整合完成

MH4G 使用独立存档核心和独立游戏数据，未复制 MH3G 偏移或装备 ID；实际复用的是交互规则、
逻辑配装概念、账号体系和广场产品流程。工作区 `mh4g-se` 已完成 SQLite、七格配装协议、
社区合法性、配装广场和一键导入的本地整合，并具备以下能力：

- 3DS 加密角色文件的打开、校验、原路径原子覆盖和不修改往返。
- 1400格道具箱、1500格装备箱和完整28字节装备记录。
- 十四类武器、五类防具、装饰珠、护石、发掘装备和猎虫的现有数据与编辑界面。
- 当前穿戴副本同步、CSV 批量传输和真实存档回归测试。

以下交接项均已完成，保留原顺序作为实现记录：

### 1. MH4G 配装数据层

- 将配装所需静态数据统一为只读 SQLite，并建立 manifest、逻辑哈希和数据版本。
- 以 `core_common.arc` 名称数组确认存档 ID；为十四武器、防具、装饰珠、技能树、发动阈值、
  防御、耐性、孔位和护石建立明确关联。
- 首批只让证据完整的普通装备参与配装和公开分享。发掘装备虽然可在装备箱中自由编辑，但其
  随机参数不能硬塞进 MH3G 的普通装备模型。

### 2. MH4G 装备合法性检测

- 在配装器之前建立公共 `EquipmentValidator`，由装备箱、单件编辑器、CSV 导入预览、配装器
  和后续服务端适配器共同使用，禁止各页面分别维护判断逻辑。
- 普通武器、防具、装饰珠和护石使用 SQLite 中的原生参数与生成规则检查真实 ID、部位、性别、
  剑士/枪手、孔位、装饰珠占孔、强化范围及护石自然组合。
- 发掘武器、防具和猎虫按已确认的字段结构、正常档位及组合证据分层诊断；证据不足的组合显示
  “未确认”，不能因为不在普通装备表中就直接判为非法。
- 延续3G原则：红色说明具体原因，但不限制编辑、导入或保存；只有记录长度、字段宽度、数组
  越界、未知类型和无法安全解析等结构错误才阻断。
- 合法性结果不写死在 UI，也不信任客户端摘要；后续平台必须使用同版本 MH4G 数据重新计算。

### 3. 本地配装器

- 复用 MH3G 的七格布局、长列表筛选、技能矩阵、风险提示和本地 dirty 分离规则。
- 按 MH4G 十四武器和4G技能规则重新实现计算器，不复制 MH3G 游戏公式。
- 先完成普通武器、防具、护石和装饰珠；发掘装备需要独立的规范字段、显示和风险策略后再接入。
- 本地配装在服务器不可用时仍须完整工作。

### 4. 一键加入装备箱

- 为 MH4G 新建独立 `LoadoutSaveBridge`，按28字节记录构造武器、五件防具和护石。
- 先预留七个空格并完成全量校验，成功后才一次性更新内存；不得直接保存、自动穿戴或破坏
  当前穿戴副本。
- 用真实加密存档验证只改变七条目标装备记录及必要校验字段，保存后可重新解密和加载。

### 5. 配装广场与平台适配

- 保留 `MH_LOADOUT` 的 `game + schema_version + data_version` 隔离，新增 `game=mh4g` 服务端适配器。
- 服务端使用 MH4G 数据重新计算装备/技能索引、合法性和风险，不信任客户端摘要。
- 复用匿名大厅、装备 AND、发动技能 AND、合法性筛选、只读详情、登录、发布查重、点赞和举报。
- 详情继续以配装器弹窗打开，再由用户主动一键加入装备箱。
- 禁止按名称或 ID 偏移把 MH3G 配装转换为 MH4G 配装，也不上传完整 MH4G 存档。

### 发掘装备协议结论

MH4G 已采用每件装备完整 28 字节实例协议，不再使用只保存外观 ID 的简化方案。攻击档、属性、
斩味、升级、专属值、稀有度、研磨、孔位、极限强化、固定珠和猎虫实例均逐字节往返；配装器
可只看发掘武器或防具，并复用现有高级编辑器。装备箱来源弹窗按原页/格显示具体实例及珠子，
因此同一外观的多件发掘装备不会混淆。

MHGU / MHXX 的接入排在 MH4G 闭环完成之后；各作只共享平台外壳和协议框架，不共享存档偏移、
数据 ID 或游戏计算规则。
